==============================================================================
1. INTRODUCTION                                             *pkm-introduction*

PKM.nvim is a personal knowledge management plugin for Neovim. It manages
a collection of markdown notes with YAML frontmatter, automatic bidirectional
citation tracking, project views, and Telescope integration.

The system is built around a three-stage workflow:

  Scratchpad  →  quick capture, no friction
      ↓
  Journal     →  timestamped entries, personal log
      ↓
  Consolidated →  permanent numbered knowledge base

Notes are plain markdown files. No proprietary formats, no cloud dependency.
All notes share a single flat namespace and a single sequential counter —
note numbers are globally unique and never reused (even after deletion).

==============================================================================
2. REQUIREMENTS                                             *pkm-requirements*

  • Neovim ≥ 0.10
  • Vitruvia/pkm-syntax              (required; the markdown highlighting, now a
                                     separate plugin — without it pkm-nvim still
                                     loads, just without highlighting)
  • nvim-telescope/telescope.nvim   (optional but strongly recommended)
  • Tree-sitter markdown parser     (bundled with Neovim 0.10+)
  • Tree-sitter yaml parser         (optional; enables frontmatter syntax)

==============================================================================
3. INSTALLATION                                             *pkm-installation*

lazy.nvim: >
  {
    'Vitruvia/pkm-nvim',
    dependencies = {
      'Vitruvia/pkm-syntax',                 -- markdown highlighting (required)
      'nvim-telescope/telescope.nvim',       -- optional
    },
    config = function()
      require('pkm').setup({
        root_path = vim.fn.expand('~/Notes'),
      })
    end,
  }
<
pkm-syntax also stands alone: `require('pkm-syntax').setup()` highlights every
markdown buffer, with no dependency on pkm-nvim.

==============================================================================
4. SETUP                                                           *pkm-setup*

Minimal: >
  require('pkm').setup({
    root_path = vim.fn.expand('~/Notes'),
  })
<

Full example with PKM Mode and trash: >
  require('pkm').setup({
    root_path = vim.fn.expand('~/Notes'),
    user = { name = "Your Name" },
    pkm_mode = {
      triggers = { open_note = true, enter_dir = false },
      layout   = { sidebar = true, bufpanel = true },
      syntax   = { enabled = true },
    },
    trash = {
      enabled      = true,
      max_age_days = 60,
    },
    keymaps = {
      new_note        = "<leader>nn",
      browse          = "<leader>ff",
      insert_citation = "<leader>cc",
      view_sidebar    = "<leader>ps",
    },
  })
<

PKM creates the folder structure under root_path on first use.
Set any keymap value to `false` to disable it.

==============================================================================
5. WORKFLOW                                                     *pkm-workflow*

CAPTURE~
Use `:PKMNote scratch` to write down ideas immediately. Scratchpads are
timestamped files in 01-Scratchpad/ and require no decisions at creation time.

JOURNAL~
Use `:PKMNote journal` for dated entries. The timestamp is recorded in the
filename and frontmatter automatically.

CONSOLIDATE~
When a scratchpad is worth keeping, use `:PKMNote promote` to move it to a
consolidated note or journal entry. Create consolidated notes directly with
|:PKMNote| (bare creates; `:PKMNote new note|agg|bib` names the type).

CONSOLIDATED NOTE TYPES~
  note   Regular knowledge note
  bib    Bibliography or reference entry
  agg    Aggregate or collection note

CITE~
Use `:PKMCite <target>` to cite another note (bare |:PKMCite| opens a picker),
or `:PKMCite insert` to insert a structured citation at the cursor. The cited
note automatically receives a backlink, maintained bidirectionally and on save.

SEARCH~                                                           *pkm-search*
Use |:PKMBrowse| for live filter-as-you-type search across all notes.
Use |:PKMTags| to browse by tag, or to add, remove or rename a tag across many
notes at once. The tag picker lists how many notes carry each tag and previews
them. Use `:PKMBrowse orphans` to find unfiled notes.

BULK ACTIONS~
Bulk operations start from the notes you have in front of you. Mark notes with
<Tab> and press <C-a>; with nothing marked, <C-a> acts on everything listed.
That works in every note picker (|:PKMBrowse|, `:PKMBrowse recent`, the sidebar's
"/" and the views tree's <C-f>), in the view sidebar (`:PKMPanel sidebar`, inside
a view; <S-Tab> marks and steps up), and in the browse mode of `:PKMBrowse views`.
Over a *view* — in the sidebar's overview or the views list — <C-a> acts on
every note that view matches; there is nothing to mark there.

The action menu is short: add, remove or rename a tag, change the title, rename
the file, or add the notes to a view / take them out of one.

CHANGING TITLES IN BULK~
One panel, and what you type is the operation. The field takes the two halves
of a `:%s` command, separated by a slash: >

    pattern/replacement

    Draft/Notas                    Draft — Kant    ->  Notas — Kant
    ^/Sobre                        Kant            ->  Sobre Kant
    $/ (rascunho)                  Kant            ->  Kant (rascunho)
    \[wip\] /                      [wip] Kant      ->  Kant
    Aula \(\d\+\)/Aula 0\1         Aula 3 - Kant   ->  Aula 03 - Kant
<
It is Neovim's own regex — the expression that works in `:%s` works here, `\v`
and `\c` included — so there is no menu of operations: an anchor is a prefix or
a suffix, and an empty replacement is a removal. Write `\/` for a literal slash.

Type only a pattern, with no slash, and the panel lists the titles that match:
you can find the expression before committing to it. Add the slash and the rows
become "before -> after", updating as you type, while the preview pane shows the
note with its new title already in the frontmatter.

<CR> applies to every note listed; <Tab> narrows to a subset first. A note that
does not match is simply not listed, an expression that would empty a title is
refused, and an invalid one is reported on the row it fails on — the rest of the
batch is unaffected. Titles are propagated too: every note citing a retitled one
has its stored copy updated, in a single pass over the vault.

The panel reopens after applying, over the notes as they now read, so a second
substitution costs nothing; <Esc> closes it. <C-b> steps back to a picker over
the same notes, for when the selection was wrong rather than the expression.

Notes you have open are kept in step: an unmodified buffer is reloaded after the
write, and one with unsaved changes is never reloaded behind your back — you are
asked (y/n) whether to save it first, and only when there is one.

PUTTING NOTES IN A VIEW~
A view is a filter, so belonging to one means satisfying it — and tags are the
only part of a note this can rewrite for you. So "Add to a view" works out which
tags make the view's filter match and applies them, previewed like any other tag
change. For `tag:projeto AND NOT tag:draft` that means adding `projeto` and
dropping `draft`.

"Remove from a view" is the same question mirrored: what makes the filter
*false*. That often has more than one answer — dropping `projeto` or adding
`draft` both work — and you are asked which, rather than having it guessed.

When a view cannot be satisfied by tags at all, because its filter also demands
something like `title:seneca` or `type:bib`, the action names that condition and
writes nothing. Tags that would not make the note match are worse than a refusal.

You are not asked *which* view when the notes came from one: a view's note list,
the sidebar, and the views picker all carry it.

RENAMING FILES IN BULK~
Same panel, same `pattern/replacement`, but over the filename — and with one
difference that matters. The `0042_note_` prefix is identity, not description:
the expression never sees it, so numbering and type survive any pattern. What
you are editing is the part after it: >

    Rascunho_/                 1001_note_Rascunho_Kant  ->  1001_note_Kant
    ^/Aula_                    1001_note_Kant           ->  1001_note_Aula_Kant
<
Journal and scratchpad notes cannot be renamed this way — their name *is* their
timestamp, which the whole ordering depends on. Selecting them is not an error;
they are reported as skipped, with the reason, and left alone.

The preview shows the new filename and how many notes cite this one, because
each of those has to be rewritten. Then, unlike titles, <CR> leads to a final
yes/no over the **whole** list: renaming rewrites [[links]] and citation entries
everywhere, and a batch that half-applies leaves dangling links. Two notes that
would end up sharing a name is refused before that gate — the number already
makes names unique, so a collision means the expression was wrong.

TAG BATCHES~
Two steps, and nothing is written until the last is confirmed:

  1. Tag      always the same picker. Adding offers every tag, ordered by
              relevance to your selection: first the ones already on some of
              the selected notes ("on 2 of 5 selected"), then tags that keep
              company with theirs ("co-occurs on 7 notes"), then the rest by
              usage, and last the ones already on all of them. Type a tag that
              does not exist and it offers to create it.
              Removing offers only the tags the selected notes carry.
              Renaming asks for the source that way, then for the destination
              from the same picker — an existing tag merges into it, a new one
              renames to it.
  2. Confirm  the note picker again, one row per affected note showing its
              "before -> after" tags. <CR> applies to everything listed, so
              narrowing or marking here drops notes from the batch;
              q/<Esc> backs out and writes nothing.

|:PKMTags| also takes arguments, for scripts and for direct access: >

    :PKMTags                       browse by tag (the bare form)
    :PKMTags add draft             add a tag
    :PKMTags remove draft          remove a tag
    :PKMTags rename draf draft     rename a tag
<
The argument form is deterministic — it targets the whole vault, not whatever
happens to be open — and still ends at the confirmation step above. Quote a
multi-word tag: `:PKMTags add "ring forge"`.

Tags already present are never duplicated, matching ignores case, and a tag
already written in the file keeps its spelling — a batch never rewrites a note
just to lower-case a tag.

VIEWS~
Use `:PKMView new` to save filter expressions as named project views.
Use `:PKMPanel sidebar` for a persistent sidebar listing a view's notes.
Use `:PKMPanel mode` to activate the full explorer interface.

DELETE / RESTORE~
Use `:PKMNote delete` to safely delete a note. With trash enabled (default),
the note moves to .pkm-trash/ and can be recovered with `:PKMTrash restore`.

6. COMMANDS                                                     *pkm-commands*

The command surface is verb-driven: ~15 context commands, each taking a verb.
`:PKM<Tab>` lists the contexts; `:PKMNote <Tab>` (etc.) lists a context's verbs.
A context with a friendly default does the common thing bare — `:PKMNote`
creates, `:PKMCite <target>` cites, `:PKMBrowse <expr>` browses.

NOTES — creation and lifecycle~                                     *:PKMNote*

:PKMNote [new] [type]   Create a consolidated note. Type: 'note', 'agg', or
        [title=…]       'bib'; prompts if omitted. `title=` sets the title with
        [by=<agent>]    no prompt; `by=<agent>` stamps agent authorship.

:PKMNote relative [type]
                        Create a consolidated note carrying the current note's
                        tags, so it falls inside the same views without
                        retyping its classification. Tags are read from the
                        buffer, so unsaved tag edits count. Prompts if omitted.

:PKMNote journal        Create a journal entry timestamped to the current time.

:PKMNote scratch        Create a new scratchpad with an optional title.

:PKMNote import         Import the current file into the PKM structure.

:PKMNote convert        Normalize the current note to its folder's format.
                        Adds missing frontmatter fields, preserves existing
                        values. Renames and prompts for type/title if the
                        filename does not follow PKM conventions.

:PKMNote promote        Promote a scratchpad to a consolidated note or journal
                        entry. Only available from 01-Scratchpad/.

:PKMNote transpose      Move the current note to a different PKM folder and
                        convert it to the appropriate type.

:PKMNote changetype     Change a consolidated note's type between note/agg/bib.
                        Renames the file and updates frontmatter fields.

:PKMNote delete         Delete the current note. With trash.enabled = true
                        (default), moves to .pkm-trash/ and preserves backlinks
                        for recovery. With trash.enabled = false, strips
                        backlinks and permanently deletes. Always use this
                        instead of deleting files manually. See also |pkm-trash|.

:PKMNote rename [name]  Prompt for a new filename (or take one as an argument).
                        Sanitizes the input, renames on disk, redirects the
                        buffer, and propagates through all citations. Does not
                        modify the title field. Works on consolidated, journal,
                        and scratchpad notes.

:PKMNote settitle [text]
                        Set the 'title' frontmatter field (buffer-only; the
                        index updates on the next :w). Prompts without an
                        argument.

CITATIONS AND LINKS~                                                *:PKMCite*

:PKMCite [add] <target> Cite a note from the current one. Bare `:PKMCite` opens
                        a context-aware picker of citable notes, pre-scored by
                        active-view membership (+2) and shared tags (+1);
                        relevant items are prefixed '~'. Writes the citation and
                        updates both notes' frontmatter bidirectionally.

:PKMCite remove [target]
                        Remove a citation (bare = picker over what this note
                        cites), updating both sides of the graph.

:PKMCite insert         Insert a citation string at the cursor via the picker.

:PKMCite link           Pick a note and insert a [[wiki-link]] at the cursor.

:PKMCite follow         Open the note referenced by the [[wiki-link]] or
                        citation under the cursor.

:PKMCite goto           Jump to the note referenced by the citation string
                        under the cursor (e.g. note[0042]).

:PKMCite backlinks      Show all notes linking to / citing the current note.

:PKMCite update         Rescan the current buffer and rebuild the 'cites'
                        frontmatter list to match in-body citations.

SEARCH AND BROWSE~                                                  *:PKMBrowse*

:PKMBrowse [expr]       Live filter-as-you-type note browser.
                        The prompt evaluates filter.lua expressions on each
                        keystroke. Examples:
                          fourier               any field contains "fourier"
                          tag:math              tag equals "math" (exact)
                          title:ring            title contains "ring"
                          text:laplace          body contains "laplace"
                          filename:0042         stem contains "0042"
                          type:note             note_type equals "note"
                          type:bib              note_type equals "bib"
                          tag:math AND title:fourier
                          (tag:math OR tag:physics) AND NOT tag:draft
                          type:note AND tag:draft

                        Valid type values: note, agg, bib, journal, scratch,
                        other. Bare text and unknown fields trigger the 'any'
                        predicate (substring across all fields simultaneously).
                        Optional [expr] pre-seeds the prompt.
                        Telescope: live. Fallback: prompt once, then select.
                        Tab-completion: field prefixes, operators, tag values,
                        type values. In the picker, <C-t> cycles a note-TYPE
                        filter (all -> note -> agg -> bib -> journal -> scratch)
                        applied on top of the prompt — the quick way to isolate
                        journal or scratchpad notes without the sidebar.

:PKMBrowse recent [n]   Show the n most recently modified notes (default 20),
                        sorted by modification time descending.
                        Telescope live picker or vim.ui.select fallback.

:PKMBrowse orphans      Show notes that have no tags, no citations (in any
                        cites/cited_by group), and do not match any defined
                        view. Useful for locating abandoned or unfiled notes.

:PKMBrowse tags         Browse notes by tag: pick a tag, then browse the notes
                        carrying it. (Editing tags is the :PKMTag surface below.)

:PKMBrowse views [name] The view pop-ups. Bare, a tree-structured picker of all
                        defined views (parent-child hierarchy, note counts);
                        a `<name>` opens that view's notes; `last` reopens the
                        last view activated this session. Tab-completes view
                        names and `last`. The persistent counterpart is
                        `:PKMPanel sidebar`; managing views is |:PKMView|.

TAGS~  `:PKMTag` one note · `:PKMTags` all notes         *:PKMTag* *:PKMTags*

:PKMTag add <tag>       Add a tag to the current note (buffer-only; the index
        [note=<ref>]    updates on the next :w). `note=<ref>` targets another
                        note on disk instead. Skips if already present.

:PKMTag remove <tag>    Remove a tag from the current note (or `note=<ref>`).
        [note=<ref>]    Picker if no tag is given.

:PKMTag merge           Merge one or more tags into a target tag across all
                        notes. Three-step Telescope picker, or fallback UI.

:PKMTags [mode] [tag] [new-tag]
                        The batch surface — operates over the WHOLE vault, not
                        just the current note. Bare, it opens the tag picker
                        (each tag with the number of notes carrying it,
                        previewing them) and opens :PKMBrowse pre-filtered to
                        the one chosen; without Telescope, a mode menu instead.
                        With arguments (browse | add | remove | rename), it runs
                        that operation over every note, ending at a change-list
                        confirmation. Completes modes and tags. To act on chosen
                        notes instead, mark them in any note picker and press
                        <C-a> — see |pkm-search|.

EXPORT~                                                             *:PKMExport*

:PKMExport [simple|deep]
                        Choose simple or deep export, then open the filter
                        form. Bare opens the mode menu. See |pkm-export|.

:PKMView export [name]  Export all notes in a named view, skipping the filter
                        form. Tab-completes view names. Without a name,
                        presents a picker.

VIEWS~                                                              *:PKMView*

`:PKMView` MANAGES view definitions (the verbs below). DISPLAYING a view is
elsewhere, by design (the persistent-vs-transient split): `:PKMBrowse views
[name]` opens a view's notes — or the view picker — as a transient pop-up, and
`:PKMPanel sidebar [name]` pins it in the persistent sidebar. See |:PKMBrowse|
and |:PKMPanel|.

:PKMView new            Prompt for a name and type (simple view or subproject),
                        then for a filter expression (and parent view if
                        subproject), and save to views.json.

:PKMView add|remove <view> [note=<ref>]
                        Add or remove a note (the current one, or `note=<ref>`)
                        to/from a view by rewriting the tags its filter needs —
                        previewed like any tag change. See |pkm-search| "PUTTING
                        NOTES IN A VIEW".

:PKMView update [name]  Open an action picker: "Edit filter expression",
                        "Rename", "Change parent" (subprojects only).
                        Rename propagates to child subprojects and session
                        state. Change parent validates against hierarchy cycles.
                        Tab-completes view names.

:PKMView rename <old> <new>
                        Rename a view, keeping its notes; propagates to child
                        subprojects and session state.

:PKMView edit           Open views.json for direct editing. Saving the file
                        reloads all views automatically.

:PKMView delete [name]  Remove a named view from views.json.
                        Tab-completes view names.

PANELS~   `:PKMPanel <verb>`                                        *:PKMPanel*

:PKMPanel [explorer]    Toggle the explorer (sidebar + buffer panel) as a unit,
                        independent of PKM Mode. If both open, close both; if
                        either is closed, open the closed one(s).

:PKMPanel buffers       Toggle the persistent bottom buffer-list panel.
                        Lists all open regular-file buffers. PKM notes show
                        type prefix [n]/[a]/[b]/[j]/[s]/[o] and title;
                        non-PKM files show filename. Modified buffers show [+].

                        Keymaps inside the panel:
                          <CR>   open buffer in main editing window
                          d      close buffer (:bdelete)
                          D      force-close buffer (:bdelete!)
                          w      write buffer then close it
                          r      refresh the list
                          T      toggle note label: filename ↔ title
                          q / <Esc>   close the panel

:PKMPanel nav           Toggle the current-file navigation panel — a heading
                        index of the note in front of you. Inside it, <CR>
                        jumps to the heading and `/` filters the list.

:PKMPanel sidebar [name]
                        Toggle the persistent view sidebar (the only command
                        that opens it). A name opens it on that view. See
                        |pkm-sidebar|.

:PKMPanel mode [on|off] Activate, deactivate, or toggle PKM Mode — the
                        session-level context that opens the explorer, pre-
                        builds the index, and enables PKM syntax highlighting.
                        Bare toggles. See |pkm-mode|.

MARKDOWN EDITING~   `:PKMHeader` · `:PKMList`       *:PKMHeader* *:PKMList*

:PKMHeader append       Duplicate the header on the current line with its
                        trailing counter incremented, append at EOF.

:[count]PKMHeader next [same|h1-h6]
:[count]PKMHeader prev [same|h1-h6]
                        Jump to the next/previous header. With no argument, any
                        level; with h1-h6, only that level; with `same`, the
                        level of the header the cursor sits under. A count that
                        overshoots stops at the last header.

                        The level is spelled h2, not 2, because a leading number
                        in the arguments IS the count: `:PKMHeader next 6` means
                        six headers ahead, not level six. (As a keymap the count
                        is a Vim count, `3]h`; on the command it is an argument,
                        `:PKMHeader next 3`.)

                        Neovim's own ]] and [[ already jump section to section.
                        These add a count, a level restriction, Visual mode, a
                        jumplist entry, and working without the tree-sitter
                        markdown parser. Headers inside YAML frontmatter or a
                        fenced code block are never targets.

:PKMHeader levelup      Increase the # depth of all headers in the range.
                        Default range: whole buffer. Accepts '<,'> prefix.

:PKMHeader leveldown    Decrease the # depth of all headers in the range.
                        Level-1 headers are protected.

:PKMList renumber       Renumber ordered-sequence items in range or paragraph.
                        Supports nested lists (per-level counter stack),
                        blockquote-prefixed lists, emphasis-wrapped ordinals
                        (*N*[.)], **N**[.)]), bold-line items (**N. body**),
                        header families, and the legal (LC 95/1998) marker
                        hierarchy (artigo/parágrafo/inciso/alínea/subalínea).
                        Range: visual selection or paragraph at cursor.

:PKMList convert [to_ordered|to_unordered]
                        Convert list items between ordered and unordered in
                        range or paragraph at cursor. Direction is auto-detected
                        (all-ordered → to_unordered; all-unordered → to_ordered;
                        mixed → prompts); nested lists prompt for the maximum
                        conversion depth. Items already in the target format are
                        preserved (ordered items renumbered to keep sequence).
                        An optional direction argument skips detection.

:PKMList wrap           Structure-aware reflow of the range or current paragraph
                        to 'textwidth' — headings and fences left intact,
                        list-item continuations aligned, blockquotes reflowed,
                        code preserved. Also wired as 'formatexpr', so gq/gw
                        route through it. See CONVENTIONS § Lists.

TRASH~   `:PKMTrash <verb>`                                        *:PKMTrash*

:PKMTrash restore       Browse and restore notes from the trash. See |pkm-trash|.

:PKMTrash empty         Permanently delete all trashed notes (confirms).

VAULTS~   `:PKMVault <verb>`                                       *:PKMVault*

A vault is a folder with its own numbering, citation graph and views; vaults
never communicate. Most setups need exactly one and can ignore this.

:PKMVault[!] [name]     Switch the active vault. No argument lists the vaults;
                        `!` also makes the named one the registry default.

:PKMVault[!] new <name> Create a vault: folder, skeleton and registry entry.
                        `!` skips creating a git repository.

:PKMVault rename <from> <to>
                        Rename a vault, keeping its number. Moves the folder;
                        touches no note.

:PKMVault renumber <name> <n>
                        Renumber a vault, keeping its name.

:PKMVault unregister [name]
                        Move a vault out of the registry into Unregistered/
                        (always confirms). No note is deleted.

:PKMVault adopt [folder]
                        Register an existing folder as a vault, contents
                        untouched — the way back from `unregister`.

UTILITIES~

:PKMCheck               Audit the vault: frontmatter completeness, the citation
                        graph, note numbering, and vault references. Reports
                        findings without modifying anything.

:PKMStats               Show note counts per folder via vim.notify.

:PKMToggleAutoSync      Toggle automatic citation-reference synchronization on
                        save (config `sync.auto_sync_on_save`).

:PKMSyntax [on|off|toggle]
                        Toggle PKM markdown highlighting on the current buffer.
                        Bare toggles. (Highlighting is provided by the pkm-syntax
                        plugin; see |pkm-requirements|.)

FOR ASSISTANTS — pkm.api~                                  *:PKMAgentProtocol*

PKM.nvim exposes a stable Lua API, `require('pkm.api')`, so an LLM coding
assistant drives the vault through the plugin's own cores instead of hand-
editing files (which desyncs the citation graph, numbering, and index). It
covers reads (retrieval, backlinks, views) and the note lifecycle — create,
body writing, rename/changetype/transpose, tag and membership writes, annotate.

  doc/PKM_API.md          the API reference (functions, arguments, returns)
  doc/AGENT_PROTOCOL.md   the doctrine: how an assistant behaves in a vault
  doc/CONVENTIONS.md      note formats, in-text citations, list markers

:PKMAgentProtocol install|update|path
                        Install (or update) the bundled `pkm-notes` skill and
                        `/pkm-learning` slash command into your assistant's
                        config, so the protocol travels with the tooling.
                        `path` reports where they were written.

                                                              *pkm-sidebar*
SIDEBAR KEYMAPS~

The sidebar (`:PKMPanel sidebar`) has two modes: overview
(all views) and detail (notes in one view). Keymaps are the same in both modes.

  <CR>     In overview: enter the view under the cursor.
           In detail, on a tree header line (▶/▼): navigate to that view.
           In detail, on a note line: open note in the main editing window.
  <C-v>    Open the note under the cursor in a new vertical split.
           (Detail mode only.)
  <Tab>    Mark the note under the cursor and step down; <S-Tab> marks and
           steps up. Marks are per note, so they survive a refresh and are
           cleared when you enter another view. (Detail mode only.)
  <C-a>    Bulk actions on the marked notes, or on every note listed when
           none are marked. In overview, on every note of the view under
           the cursor. See |pkm-search|.
  <C-t>    Cycle the type filter: all → note → agg → bib → journal →
           scratch → all. Filters the note list and shows "N of M" count.
           (Detail mode only; resets to all on return to overview.)
  N<CR>    Open the note in the Nth editing window, counted left to right
           (1 = leftmost). Falls back with a warning if N exceeds the
           number of open editing windows.
  T        Toggle note label between filename stem and frontmatter title.
           Applies simultaneously to the sidebar, buffer panel, and winbar.
           Persists for the session; resets to config.display_mode on restart.
  b        Back: pop the navigation history stack; fall back to overview
           if the stack is empty.
  <BS>     Same as b.
  <C-b>    Jump directly to overview, pushing current state to history.
  /        Scoped search: in detail mode, opens the filter picker over the
           view's notes; in overview, opens the global :PKMBrowse.
           Focus switches to the main editing window first so files open
           there, not over the sidebar.
  r        Refresh current mode in place.
  <C-n>    Cycle the sidebar content: views (this panel) <-> nav (the focused
           note's heading index). The same sidebar hosts both; this switches
           which one it shows. (See also |pkm-panel-keymaps| for nav's keys.)
  q / <Esc>  Close the sidebar.
  ?        Show this keymap help as a floating window.

  <C-s>    No-op (prevents global split keymaps from acting on the sidebar).

Type prefixes shown in the note list:
  [n] note   [a] agg   [b] bib   [j] journal   [s] scratch   [o] other

7. PKM MODE                                                       *pkm-mode*

PKM Mode is a session-level context toggle that activates the full explorer
interface and PKM-specific syntax highlighting.

:PKMPanel mode [on|off] Activate, deactivate, or toggle PKM Mode.
                        Without an argument, toggles.
                        on  → opens sidebar + buffer panel, pre-builds index,
                              enables tree-sitter syntax on all PKM buffers
                        off → closes both panels, reverts syntax to default

:PKMPanel [explorer]    Toggle sidebar + buffer panel as a unit, independent
                        of PKM Mode state. If both open: close both. If
                        either closed: open the closed one(s).

SYNTAX HIGHLIGHTING (PKM MODE)~

When active, PKM Mode enables tree-sitter-based highlighting:
  • Frontmatter `---…---` block folded by default.
    Fold commands (cursor must be on or inside the frontmatter):
      za   toggle fold (open if closed, close if open)
      zR   open all folds (expand frontmatter)
      zM   close all folds (re-hide frontmatter)
    Note: entering insert mode auto-opens folds (standard Neovim behaviour);
    use za or zM to re-close without saving.
  • `note[0042]`, `bib[0003]` etc. highlighted as PKMCitation (→ Special)
  • `((text))` double-paren meta-comments highlighted as PKMMetaComment (→ Comment)
  • YAML frontmatter syntax via injected yaml parser (if installed)
  • 4-space-indented text suppressed (no code-block colour)
  • List markers visible at all nesting depths

AUTO-TRIGGER~

Configure `pkm_mode.triggers.open_note = true` (default) to automatically
activate PKM Mode when any PKM note is opened. If mode is already active,
only syntax is enabled on the new buffer — panels are not re-opened.

8. TRASH                                                         *pkm-trash*

When `trash.enabled = true` (default), `:PKMNote delete` moves notes to a
`.pkm-trash/` folder inside the PKM root instead of permanently deleting them.

  • Backlinks in other notes are NOT stripped on trash. They are preserved so
    restoration requires no reconstruction work.
  • Trashed notes do NOT appear in :PKMBrowse, views, `:PKMBrowse orphans`, or
    the sidebar. The only access point is `:PKMTrash restore`.
  • Note numbers are never reused — if note 0042 is trashed and you create a
    new note, the new note becomes 0043. Gaps are intentional.

:PKMTrash restore       Open a picker over all trashed notes (showing title,
                        deletion date, and original path). Selecting an entry
                        moves the file back to its original location and
                        re-adds it to the index. Backlinks require no repair.

:PKMTrash empty         Permanently delete all trashed notes. Strips backlinks
                        in other notes via cleanup_deleted_note for each entry.
                        Requires typing 'yes' to confirm.

AUTO-PURGE~

Set `trash.max_age_days` (default 60) to automatically purge entries older
than N days on Neovim startup. Set to 0 to disable. A notification is shown
when entries are purged. To disable trash entirely and revert to permanent
delete, set `trash.enabled = false`.

TRASH LOCATION~

  {root_path}/.pkm-trash/             trashed note files
  {root_path}/.pkm-trash/manifest.json  records of each trashed note

The trash folder and manifest are inside the PKM root; they move with the
notes and can be version-controlled. The manifest stores the original path,
deletion timestamp, and title of each trashed note.

9. CITATIONS                                                   *pkm-citations*

CITATION FORMAT~

Citations are written inline as: >
  note[0042]
  bib[0003]
<
The number is the four-digit note number. The prefix identifies the note type.

INSERTING A CITATION~

Use `:PKMCite insert` (or bare |:PKMCite|, or the keymap). A context-aware
picker shows all notes, pre-scored by:
  +2  if the note is in the active view (`:PKMPanel sidebar` or last `:PKMBrowse views`)
  +1  per tag shared with the current note

Relevant items are prefixed `~ ` and sorted to the top.

Selecting an item inserts the citation string and immediately:
  1. Adds the cited note to the current file's `cites.notes` or `cites.bib`
  2. Adds the current file to the cited note's `cited_by.notes` or `cited_by.bib`

If the cited note's buffer is open and modified, the backlink is applied
directly to the buffer without writing to disk, preserving unsaved changes.

FRONTMATTER STRUCTURE~
>
  cites:
    notes:
      - identifier: note-0042
        title: "Note Title"
        link: "[[0042_note_Note_Title]]"
    bib:
      - identifier: bib-0003
        title: "Source Title"
        link: "[[0003_bib_Source_Title]]"
  cited_by:
    notes: []
    bib: []
<

10. EXPORT                                                       *pkm-export*

:PKMExport opens an interactive filter form. `:PKMView export [name]` exports
a named view's notes directly without the form.

THE FILTER FORM~
>
  ╭─ PKMExport: Advanced Filter ─────────────────────────────────────╮
  │  Tags ANY  (OR) :                                                 │
  │  Tags ALL (AND) :                                                 │
  │  Title contains :                                                 │
  │  Text  contains :                                                 │
  ╰───────────────────────────────────────────────────────────────────╯
<

All active fields are AND-ed together. Matching is exact substring — never
fuzzy. After filtering, a Telescope picker (or scrollable float) opens.

In the picker, <CR> exports every note currently listed — typing in the prompt
narrows that list by exact substring. To export only some of them, mark those
with <Tab> (<S-Tab> marks upward) and then press <CR>; with marks present only
the marked notes are exported. The no-Telescope float behaves the same way:
<CR> exports the whole list. Then enter a destination folder path.

SIMPLE VS DEEP~

:PKMExport first asks which mode to use:

  Simple    Export the notes you select in the picker.
  Deep      The same, except the notes you select are treated as starting
            points: the notes they cite — and, if asked, the notes citing
            them — are exported alongside.

Both modes run the same first two steps, so the gesture is unchanged: filter,
then mark what you want with <Tab>. Deep only changes what happens after you
confirm. Marking one note therefore exports that note's neighbourhood and
nobody else's, however loose the filter was.

Deep mode asks for two depths before the filter form:

  Depth along cites      how many citation hops to follow forward   (default 2)
  Depth along cited_by   how many hops to follow backward           (default 1)

Both are counted from the notes you selected, and one path may mix directions:
it may spend up to "cites" hops forward and "cited_by" hops backward, in any
order. Blank accepts the default; 0 disables that direction. All citable types
are followed (notes, bib, journal, scratch) and cycles terminate. After the
walk, a message reports how many notes the selection grew into, and then the
destination prompt appears.

12. KEYMAPS                                                      *pkm-keymaps*

Default keymaps (all overridable; set to false to disable). The organizing line
is PERSISTENT vs TRANSIENT. CONTENT verbs say *what* you do — `<leader>n` notes,
`<leader>c` citations/links, `<leader>f` find, `<leader>v` views, `<leader>M`
markdown — and a find/view action may flash a transient picker. `<leader>p` is
the PERSISTENT panels you toggle and live with (sidebar, buffer bar); a bare key
toggles. WINDOW keys stay yours — pkm adds only `<C-Tab>`/`<C-S-Tab>` to cycle
the persistent panes. So the cyclable pop-up, a transient picker, lives under
find (`<leader>fp`), not under `p`. This section is the reference; `:nmap
<leader>` or which-key shows what is actually mapped now (every bind carries a
`PKM: …` description).

NOTES — the note lifecycle (<leader>n)~
  <leader>nn   :PKMNote            (create a consolidated note)
  <leader>nj   :PKMNote journal
  <leader>ns   :PKMNote scratch
  <leader>nr   :PKMNote rename
  <leader>nd   :PKMNote delete
  <leader>ni   :PKMNote import
  <leader>nx   :PKMNote convert
  <leader>np   :PKMNote promote
  <leader>nT   :PKMNote transpose
  <leader>nC   :PKMNote changetype

CITATIONS AND LINKS (<leader>c)~
  <leader>cc   :PKMCite insert
  <leader>cg   :PKMCite goto
  <leader>cl   :PKMCite link
  <leader>cb   :PKMCite backlinks
  gf           :PKMCite follow      (non-leader; overrides goto-file)

FIND AND SEARCH (<leader>f)~
  <leader>ff   :PKMBrowse
  <leader>ft   :PKMBrowse tags
  <leader>fp   cyclable pop-up   (nav; <C-l> cycles browse/views/nav inside it)

VIEWS — saved filters (<leader>v)~
  <leader>vl   :PKMBrowse views last
  <leader>va   :PKMBrowse views       (pick/open a view)

PANES — the PERSISTENT surfaces you toggle and live with (<leader>p)~
  <leader>ps   sidebar             (:PKMPanel sidebar)
  <leader>pb   buffer panel        (:PKMPanel buffers)
  <leader>P    focus into/out of the sidebar
  <C-Tab>      cycle focus among open panes (forward)
  <C-S-Tab>    cycle focus among open panes (backward)
  Note: the cyclable pop-up is transient — it is <leader>fp under find, not a
  pane. <leader>pn (below) makes the sidebar *show* nav; that is a pane, and is
  not the same surface as the pop-up.

MARKDOWN EDITING (<leader>M, and ]h / [h)~
  <leader>Mh   :PKMHeader append
  <leader>M^   :PKMHeader levelup    (normal and visual)
  <leader>M_   :PKMHeader leveldown  (normal and visual)
  <leader>Mr   :PKMList renumber     (normal and visual)
  ]h           next header of the current header's level
  [h           previous header of the current header's level
  [H  ]H       previous / next SHALLOWER header (toward the title);
               [H = parent, 2[H = grandparent (count = the Nth shallower)
  [L  ]L       previous / next DEEPER header (into subsections);
               ]L = first child ahead (count = the Nth deeper)
               (markdown buffers only, normal and visual, count-aware;
               any-level jumps are Neovim's own ]] and [[ )

Off by default — assign a key to enable~
  new_relative     :PKMNote relative
  set_title        :PKMNote settitle
  add_tag          :PKMTag add
  remove_tag       :PKMTag remove
  nav_panel        :PKMPanel nav        (sidebar → heading index)  e.g. <leader>pn
  explorer         :PKMPanel explorer   (sidebar + buffer panel)   e.g. <leader>pe
  toggle_mode      :PKMPanel mode                                  e.g. <leader>pm
  convert_list     :PKMList convert     (normal and visual)
  toggle_syntax    :PKMSyntax toggle
  header_next      any-level header motion (this is ]] )
  header_prev      any-level header motion (this is [[ )
  toggle_file_explorer   toggle netrw / PKM views sidebar

PANEL KEYMAPS                                              *pkm-panel-keymaps*

The keymaps above are the GLOBAL keys. Each panel also has its OWN keys, live
only while that panel is focused. They are not overridable through the config
`keymaps` table (which governs the global keys); they are the panel's fixed UI.

SIDEBAR (views + nav)~
  The full sidebar key list — <CR>, /, r, <C-t>, <Tab>/<S-Tab>, <C-a>, T, b,
  <C-b>, <C-n> (cycle views <-> nav), q/<Esc>, ? — is documented in its own
  section: see |pkm-sidebar|. In the nav (heading-index) content the working
  keys are <CR> jump to the heading, / search the headings, r refresh, <C-n>
  cycle back to views, q/<Esc> close, ? help.

BUFFER PANEL (`:PKMPanel buffers`, <leader>pb)~
  <CR>       Open the buffer under the cursor in the main editing window.
  [count]<CR>  Open it in the Nth editing window, counted left to right
             (1 = leftmost); warns if N exceeds the open editing windows.
  <C-v>      Open it in a vertical split to the RIGHT of the editing area.
  <C-x>      Open it in a vertical split to the LEFT. (Vertical only — the
             panels do not use horizontal splits.)
  /          Fuzzy pop-up over the open buffers (when too many to scan).
  <C-g>      Echo the full path of the buffer under the cursor.
  d          Close the buffer under the cursor (prompts to save if modified).
  q / <Esc>  Close the buffer panel.

BROWSE / VIEWS PICKERS (Telescope: :PKMBrowse, <leader>ff, view note lists,
the <leader>fp pop-up)~
  <Tab> / <S-Tab>  Mark / unmark the note under the cursor.
  <C-a>      Run a bulk action on the marked notes — or, with none marked, on
             every note currently listed. See |pkm-search|.
  <C-t>      Cycle the note-type filter, applied on top of the typed prompt:
             all -> note -> agg -> bib -> journal -> scratch -> all. (This is
             the non-sidebar way to reach journal/scratchpad notes.)
  <C-l>      In the cyclable pop-up (<leader>fp) only: switch to the next
             content provider (browse -> views -> nav). A no-op elsewhere.
  The prompt takes the descriptor language (tag:, text:, title:, filename:,
  type:, AND/OR/NOT, quotes) as well as plain text — see |pkm-search|.
